# PCステータス・ダッシュボード

友達のPCで「今何のアプリ/ゲームを開いているか」を一覧で見られるツールです。
1分以上マウス/キーボード入力が無い場合は自動的に **AFK** と表示されます。
さらに、本人が「お風呂中」「準備中」のようなカスタムステータスを何分間か指定して公開することもできます。

ダッシュボードは中継サーバーから直接配信されるので、**リンクを1つ共有するだけ**で、自分だけでなく友達を含めた全員が同じ画面を見られます。参加者自身も agent.py を動かせば、自分のステータスを他の人に見せることができます(あなたもその一人として参加できます)。

## 全体構成

```
[PC1: agent.py] --POST(WRITE_TOKEN)--\
                                       > [中継サーバー relay-server]
[PC2: agent.py] --POST(WRITE_TOKEN)--/         |
                                                | GET /dashboard?token=VIEW_TOKEN
                                                v
                                  [みんなのブラウザ(あなた・友達1・友達2...)]
```

- **relay-server**: 状態を一時的に保存し、`/dashboard` でダッシュボード画面そのものも配信する軽量Node.jsサーバー (`relay-server/`)
- **agent.py**: 状態を共有したい各PCで動かす常駐スクリプト (`agent/`)。設定は `config.json` に外出し
- ダッシュボードは **URLを開くだけ**で見られます。ローカルにファイルを配る必要はもうありません

トークンは2種類あります。

| トークン | 用途 | 共有範囲 |
|---|---|---|
| `WRITE_TOKEN` | agent.pyが状態を書き込むための鍵 | **絶対に他人に見せない**(なりすまし防止) |
| `VIEW_TOKEN` | ダッシュボードを見るための鍵 | 見てほしい人(友達含む)に共有してOK |

書き込み用と閲覧用を分けているので、ダッシュボードのリンクを友達に渡しても、
その友達が他人になりすまして状態を書き込むことはできません。

## 1. 中継サーバー(relay-server)をデプロイする

友達PCと全員のブラウザからアクセスできる場所に置く必要があるので、
どこかのホスティングサービスに常時起動させておきます。Node.js標準ライブラリのみで動くので、
Node.jsが動く環境ならほぼどこでも動きます。

無料枠があって手軽な例: **Render.com** (Web Service)

1. `relay-server/` フォルダの中身(`server.js`, `package.json`, `public/dashboard.html`)をGitHubリポジトリにアップロード
2. Renderで「New +」→「Web Service」→ そのリポジトリを選択
3. Build Command は空欄のままでOK(依存パッケージが無いため)、Start Command は `node server.js`
4. 「Environment」タブで環境変数を設定
   - `WRITE_TOKEN` : 長いランダム文字列(agent.py専用の秘密の合言葉。他人に見せない)
   - `VIEW_TOKEN` : 長いランダム文字列(ダッシュボード閲覧用。友達に共有してOK)
   - `OFFLINE_THRESHOLD_MS` : 省略可。デフォルト30000(30秒)
5. デプロイが終わると `https://xxxxx.onrender.com` のようなURLが発行されます

これで以下の2つのURLが決まります。

- agent.py の `server_url` に設定する値: `https://xxxxx.onrender.com/api/status`
- みんなで見るダッシュボードのURL: `https://xxxxx.onrender.com/dashboard?token=VIEW_TOKENの値`

> 補足: すでにDiscordボットをDiscloudでホストされているとのことなので、Discloudが一般的なWebアプリ(HTTPポート待受)の常時稼働に対応していれば、同様に `relay-server/` をそのままデプロイできます。Botホスティング専用で外部からのHTTPアクセスに対応していない場合は、Render / Railway / Glitch など汎用のNode.jsホスティングを使ってください。

### ローカルで動作確認したい場合

```bash
cd relay-server
WRITE_TOKEN=writetest VIEW_TOKEN=viewtest PORT=3000 node server.js
```

別ターミナルで:

```bash
curl -X POST http://localhost:3000/api/status \
  -H "Authorization: Bearer writetest" \
  -H "Content-Type: application/json" \
  -d '{"id":"pc1","label":"テスト","status":"VALORANT","isAfk":false}'
```

ブラウザで `http://localhost:3000/dashboard?token=viewtest` を開けば表示を確認できます。

### 更新(アップデート)を配る時について

- **ダッシュボードの見た目や機能を直したい** → `public/dashboard.html` を書き換えてサーバーを再デプロイするだけで、全員が次回アクセス時に新しい画面を見られます。各自のPCで何かを設定し直す必要はありません。
- **agent.pyのロジックを直したい**(バグ修正や機能追加) → 下の「自動アップデート」を設定しておけば、友達に毎回ファイルを送り直してもらう必要はありません。設定していない場合は、各PCの `agent.py` / `status_logic.py` / `local_status_server.py` を新しいものに差し替えます。設定値は `config.json` に分離してあるので、上書きしても消えません。
- **参加者を増やす/減らす** → ダッシュボードは接続してきたPCを自動的に一覧表示するので、`dashboard.html` 側の編集は不要です。新しいPCで agent.py を設定して動かすだけで一覧に加わります。

### 自動アップデートを設定する(ファイルの手動配布を無くす)

agent.pyは起動するたびに「もっと新しいバージョンが公開されていないか」をチェックし、あれば自動でダウンロード・適用して再起動する仕組みを持っています。これを設定しておくと、あなたがコードを直してGitHubにアップロードするだけで、友達のPCにも次回起動時(=次回ログイン時)に自動で反映されます。ファイルをDiscordなどで送り直す必要が無くなります。

**設定手順**

1. `agent`フォルダの中身(`FILES` に書いてあるファイルと、`VERSION`・`FILES` 自体。`extension` フォルダも含む)を、relay-serverと同じGitHubリポジトリに `agent` というフォルダ名でアップロードする(Renderのデプロイには影響しません。server.jsだけがNode側で使われます)。`config.json` は**絶対にアップロードしない**でください(合言葉が入っています)
2. 各PCの `config.json` に以下を追記
   ```json
   "auto_update_enabled": true,
   "update_base_url": "https://raw.githubusercontent.com/あなたのGitHubユーザー名/pc-status-relay/main/agent"
   ```
3. 以後、コードを直したら
   - `VERSION` ファイルの中身を書き換える(例: `1.1.0` → `1.2.0`。数字を上げるだけでOK、ルールはありません)
   - `agent`フォルダの中身をGitHubにアップロードし直す
   - ファイルを増やした時は、`FILES` にもそのファイル名を書き足す
   - 友達のPCは、次に起動した時か、起動中なら30分以内に自動で新しいバージョンに切り替わります(コンソールに `[アップデート] 更新しました` と出て自動的に再起動します)。カスタムステータスや曲の共有の最中は、消えてしまわないように更新を後回しにします

**仕組みの補足(1.3.0から)**: 新しいバージョンの agent.py は、`VERSION` が手元と違うか、`FILES` に書かれたファイルが手元に無ければ、`FILES` のファイルを全部ダウンロードし直します。1.1.0 以前の古い仕組みは3つのファイルしか取りに行けませんでしたが、その3つに agent.py が含まれているので、「古い仕組みが新しい agent.py を取ってくる → 新しい agent.py が残りを全部取ってくる」という2段階で、古いPCも最新までたどり着けます。

**セキュリティ上の注意**: この仕組みは「指定したURLから取得したコードを自動的に実行する」機能です。あなたのGitHubアカウントが乗っ取られたり、リポジトリのURLを書き換えられたりすると、友達のPCで意図しないコードが実行されるリスクがあります。信頼できる身内利用が前提の機能だと理解した上でお使いください。不安な場合は `auto_update_enabled` を `false` にすれば、これまで通り手動でのファイル差し替えに戻せます(コード自体にWRITE_TOKENなどの秘密情報は含まれていないので、リポジトリを公開しても情報漏えいにはなりません)。

## 2. 各PCに agent.py を配布する(自分のPCでも可)

Windows専用です(`pywin32` を使用)。あなた自身が参加する場合も同じ手順です。

### 2-1. ファイルの配置とライブラリのインストール

`agent/` フォルダ一式を、そのPCの好きな場所にコピーします。中のファイルの配置は変えないでください。
(自動アップデートを設定済みなら、`agent.py`・`status_logic.py`・`local_status_server.py`・`requirements.txt`・`VERSION`・`config.json` だけを置けば、残りは初回起動時に自動でダウンロードされます。)

Python 3が入っていなければ [python.org](https://www.python.org/) からインストール後、コマンドプロンプトで:

```
pip install -r requirements.txt
```

### 2-2. 初回起動と設定編集

```
python agent.py
```

初回は `config.json` が無いため、雛形を自動生成していったん終了します。
生成された `config.json` をテキストエディタで開き、以下を書き換えます。

| 項目 | 内容 |
|---|---|
| `server_url` | `https://xxxxx.onrender.com/api/status` |
| `write_token` | relay-serverに設定した `WRITE_TOKEN` と**全く同じ値** |
| `pc_id` | このPCを識別するID。**全PCで必ず別の値にする** (例: `"toro"`, `"friend2"`, `"ibuki"`) |
| `pc_label` | ダッシュボードに表示される名前 |
| `afk_threshold_sec` | AFK判定の秒数(デフォルト60=ご要望どおり) |
| `local_ui_port` | カスタムステータス設定画面のポート番号(デフォルト8787) |
| `auto_update_enabled` | 自動アップデートを使うか(デフォルトtrue。詳細は下記) |
| `update_base_url` | 自動アップデート用のコード配布URL(未設定なら自動アップデートは何もしない) |
| `show_tray_icon` | タスクバー右下にアイコンを表示するか(デフォルトfalse。詳細は下記) |
| `dashboard_url` | トレイアイコンをクリックしたときに開くダッシュボードのURL(`?token=...`込み)。空ならこのPC自身のカスタムステータス設定画面を開く |
| `music_enabled` | 「一緒に聴く」を使うか(デフォルトtrue。詳細は「5. 一緒に聴く」) |
| `listen_room` / `listen_password` / `music_service` / `music_hotkey` / `music_sound` | 「5. 一緒に聴く」を参照 |
| `update_check_interval_min` | 起動中に新しいバージョンを確認する間隔(分、デフォルト30。0で起動時だけ) |

保存後、もう一度 `python agent.py` を実行すると、数秒おきに `[送信:自動] status=...` のようなログが出て動作します。

### 2-3. 自動起動

**方法A: スタートアップフォルダ(簡単・コンソール非表示)**

1. `start_agent_hidden.vbs` を `agent.py` と同じフォルダに置く
2. `Win+R` → `shell:startup` でスタートアップフォルダを開く
3. `start_agent_hidden.vbs` のショートカットをそのフォルダに作成

**方法B: タスクスケジューラ(より確実)**

1. タスクスケジューラで「ログオン時」にトリガー
2. 操作: プログラム `pythonw.exe`、引数に `agent.py` のフルパス
3. 「ユーザーがログオンしているかどうかにかかわらず実行する」を有効にすると安定します

## 3. カスタムステータスを設定する(お風呂・準備中など)

agent.py を動かしているPC自身のブラウザで、次のURLを開きます。

```
http://127.0.0.1:8787/
```

(ポート番号は `config.json` の `local_ui_port` に合わせてください。**このURLは同じPC上からしか開けません** — 外部やインターネットからはアクセスできない作りになっています。)

「お風呂 (20分)」「準備中 (15分)」のようなワンクリックボタンに加え、自由なテキストと分数も指定できます。
設定すると、指定した時間が経つまで自動検出(ウィンドウ名 / AFK判定)より優先してそのテキストが表示され、
時間が経過すると自動的に普段の表示に戻ります。「今すぐ解除」ボタンでいつでも手動解除も可能です。

## タスクバーにアイコンを表示していつでも開けるようにする(自分のPCだけで使う場合)

音量ボタンのように、タスクバー右下(通知領域)に小さなアイコンを常駐させ、クリックだけでダッシュボードやカスタムステータス設定画面を開けるようにできます。友達のPCまで一律で増やしたいものではないと思うので、**デフォルトではオフ**になっています。自分のPCだけで使いたい場合は`config.json`で個別に有効にしてください。

**有効にする手順**

1. `pip install -r requirements.txt` を再実行(`pystray`と`Pillow`が追加されています)
2. `config.json`に以下を追加
   ```json
   "show_tray_icon": true,
   "dashboard_url": "https://pc-status-relay.onrender.com/dashboard?token=VIEW_TOKENの値"
   ```
   (`dashboard_url`を空にしておくと、代わりにこのPC自身のカスタムステータス設定画面が開きます)
3. `python agent.py`を再起動

**使い方**

- タスクバー右下にアイコンが出ます(最初は「隠れているアイコンを表示する」の`^`マークの中に入ることが多いので、ドラッグして常に見える位置に出しておくと便利です)
- **左クリック(またはダブルクリック)** → `dashboard_url`が開く(ブラウザで)
- **右クリック** → メニューが出て、「ダッシュボードを開く」「カスタムステータス設定を開く」「一緒に聴くのをリクエストする(共有中は「終了する」「退出する」)」「終了」を選べます

## 4. みんなでダッシュボードを見る

次のURLを、見てほしい人全員(自分・友達)に共有します。

```
https://xxxxx.onrender.com/dashboard?token=VIEW_TOKENの値
```

ブラウザで開くだけで、5秒おきに自動更新される一覧が表示されます。ファイルを個別に配ったり、
各自が設定を編集したりする必要はありません。

表示される内容:
- 緑の丸 = オンライン(直近 `OFFLINE_THRESHOLD_MS` 以内に受信あり) / グレーの丸 = オフライン
- 状態テキスト = フォアグラウンドウィンドウのタイトル / AFK / カスタムステータスのいずれか
- カスタムステータス中は紫の「カスタム(あとN分)」バッジ、AFK中はオレンジの「離席中」バッジ
- 小さい灰色の文字 = 実行ファイル名
- 最終更新: 何秒前に受信したか
- 継続時間: 今のアプリ/AFK/カスタムステータスがどれくらい続いているか(例: 「継続時間: 1時間30分」「このステータスになってから: 12分」)。ウィンドウタイトルが多少変わっても同じアプリ(実行ファイル)である限りリセットされません

カスタムステータス設定画面(`http://127.0.0.1:8787/`)は、Windowsのダーク/ライトモード設定に自動で合わせて表示されます。

## 5. 一緒に聴く(Apple Music・Spotify・YouTube Music・YouTube)

ブラウザ版の Apple Music・Spotify・YouTube Music・YouTube で、同じ曲を同時に聴く機能です。YouTube Premium の人は YouTube Music か YouTube を選べます。**サービスが違っても大丈夫です**(例: 自分は Apple Music、友達は Spotify)。中にいる人は全員が曲を変えられ、誰かが曲を選ぶ・再生する・止める・シークすると、ほかの人もそれぞれ自分のサービスで同じ曲が同じ位置で流れます。

### 仕組み

- エージェントを動かしているPCは、それぞれ中継サーバーに自分の「部屋」を持っています(`config.json` の `listen_room`。空なら `pc_id`)。
- **部屋のホストは同時に1人だけ**です。部屋が閉じている時は、パスワードを知っている人ならだれでもホストとして開けます(下の「だれでもホストできる」)。すでにだれかがホストをしている時に開こうとすると、その部屋に参加になります。ホストが部屋から出ると、残っている人にホストが引き継がれます(部屋を開いておくエージェントがいればそのPC、いなければ先に入った人)。全員が出ると部屋は閉じます。
- 曲を読み取る・同じ曲を探して流すのは、ブラウザ拡張機能の仕事です。拡張機能は部屋の中の人と中継サーバー経由でやり取りします。
- サービスをまたいで同じ曲を探す時は、各サービスの中で検索します。Apple Music と Spotify は ISRC(曲ごとの世界共通の番号)で探すのでほぼ正確です。YouTube Music と YouTube は動画の番号が共通なので、その2つの間はそのまま同じ動画を開きます。それ以外で YouTube Music や YouTube が関わる時は、曲名とアーティストで探し、合っている候補の中から**元の曲と長さがいちばん近いもの**を選びます。曲名に「Live」「Acoustic」「Slowed」「Karaoke」「Cover」「Remix」などが付いた別バージョンは、元の曲もそのバージョンでない限り選びません。長さが同じくらいなら、公式の音源(YouTube の「〜 - Topic」の動画、YouTube Music の「曲」)を、ミュージックビデオより優先します。アーティスト名が比べられるのに合わない候補(ほかの人のカバーや、同じ題名の別の曲)は選びません。Apple Music はストアによって名前の書き方が違います(日本のストアは海外のアーティスト名がカタカナ、カナダなどのストアは日本の曲がローマ字)。そのため、英語の名前と日本のストアでの名前(日本語)も一緒に送り、相手はそのすべてで探します。YouTube の動画のタイトルからは曲名とアーティストを取り出して使いますが、タイトルの付け方によってはうまく取り出せないことがあります。年齢制限などで流せない動画は、次に長さが近い候補を試します。見つからなかった曲はスキップされ、画面に知らせが出ます。
- **言語の違う曲名**: 日本のストア・日本語の画面で選ばれた曲は、曲名やアーティスト名が日本語(カタカナ)で届きます。受け取った側は、次の順番で探します。
  1. まず、送った人の言語で探します。YouTube Music と YouTube は送った人の言語で検索し、Apple Music は自分の国のストアに加えて送った人の国のストアでも探します(同じ曲が自分の国のストアにあればそれを流します)。
  2. 見つからなければ、Apple の公開カタログ(iTunes Search API。ログイン不要)で、その曲の「自分の国・言語での名前」(例: シェイク・イット・オフ / テイラー・スウィフト → Shake It Off / Taylor Swift)を調べて、その名前で探し直します。
  3. それでも見つからなければ、音楽ページの右下に「見つかりませんでした」と「探す」ボタンが出ます。押すと自分のサービスの検索画面が開くので、同じ曲を流してください。その曲をみんなの曲の代わりにして同じ位置に合わせ(ほかの人には送りません)、次から同じ曲が来た時は最初からその曲を流します(拡張機能が覚えておきます)。
- **再生中の秒数は常に合わせ続けます**(ずれが大きくなると自動でシークします)。Spotify は画面下の再生位置のつまみが5秒刻みなので、再生位置はバーの伸び具合と時計の表示から1秒より細かく読み取っています。キュー(次に流れる曲)は共有しません。曲が終わって次の曲に進む時は、**その曲を選んだ人のキュー**の次の曲に、ほかの人が合わせます。ほかの人のプレイヤーが曲の終わりに自分のキューや「おすすめの曲」を始めた時は、その曲を一時停止して、選んだ人の次の曲が届くのを待ちます(サービスによって同じ曲でも長さが違い、先に終わることがあるため)。この曲はほかの人には送りません。待っている間に自分で再生ボタンを押した時は、待ち時間が過ぎてから、その曲をみんなに送ります。
- YouTube(www.youtube.com)では、カテゴリが「音楽」の動画と、「〜 - Topic」のチャンネルの動画だけを曲として送ります。ゲーム実況などの動画を開いても、ほかの人には流れません。
- 誰かのところで広告が流れている間は、その人の広告が終わるまで待ってから合わせます。

### 友達と(Ctrl+Alt+M)

1. どの画面にいても `Ctrl+Alt+M` を押すと、友達のPCに「一緒に聴く」のリクエストが届きます(トレイアイコンのメニューや、音楽サービスの画面右下の 🎧 ボタンからも送れます)。
2. 友達のPCでは、通知音と一緒に画面右下に小さなポップアップが出ます。フォーカスを奪わないので作業の邪魔になりません。60秒で消えます。
3. 友達が「許可」を押すと、友達があなたの部屋に入ります。
4. 終わる時は、もう一度 `Ctrl+Alt+M` を押すか、音楽サービスの画面右下のボタンを押します。入った側なら「退出」、部屋の持ち主なら「終了」(全員が部屋から出ます)です。
5. 入った側が音楽サービスのタブを全部閉じると、その人は部屋から出たことになります(持ち主に知らせが出ます)。また一緒に聴くには、もう一度リクエストを受け取って許可します。

`Ctrl+Alt+M` を押した時は、友達のPCに加えて、拡張機能だけで前に参加したことのある人のうち、今ブラウザを開いている人にも招待が届きます。

### 参加している人の表示

- 音楽サービスの画面右下に「🎧 一緒に聴いています(3人)」と、参加中の人が1人ずつ(人のアイコン・名前・使っているサービス)並びます。自分のアイコンは赤です。
- ブラウザ右上の拡張機能アイコン(赤いヘッドホン)には、部屋にいる人数が数字で付きます。押すと、参加中の人の一覧と、前に参加した人(オンラインかどうかと、1人ずつの「招待」ボタン)が見られます。
- 拡張機能と参加ページの表示は、初めは英語です。拡張機能はアイコンを押した画面の右上、参加ページはページの右上にある地球のマークから、日本語に切り替えられます。拡張機能で選んだ言語は、音楽ページの表示と通知にも使われます。

### Discord のリンクから(パスワード付き・拡張機能だけ)

`config.json` に次の2つを書くと、エージェントを入れていない人も、リンクからパスワードで部屋に入れます。**これから新しく使う人は、PCステータス(エージェント)は入れずに、拡張機能だけ入れればよい**です。

```json
"listen_room": "skeliy",
"listen_password": "好きなパスワード"
```

- 参加ページのURLは `https://xxxxx.onrender.com/listen/skeliy` です(`listen_room` の値)。
- 開いた人は、名前・使っているサービス・パスワードを入力します。拡張機能が入っていなければ、そのページに入れ方(Windows はコマンド1つ、Mac などは zip)が表示されます。
- 誰かが入ってきた・出ていった時は、あなたのPCに通知音とポップアップで知らせます。
- パスワードを10分間に8回間違えると、そのIPからはしばらく試せなくなります。

**拡張機能だけの人の流れ**

1. 最初の1回だけ、参加ページで名前・サービス・パスワードを入れて部屋に入ります。
2. その人が音楽サービスのタブを全部閉じると、部屋から出たことになります。
3. 次からは、パスワードを入れ直す必要はありません。一度入った部屋の「通行証」が拡張機能に保存され、**その部屋でだれかが曲を流していると、拡張機能アイコンに青い「♪」が付きます**。アイコンを押すと「参加できる部屋」に、部屋にいる人と流れている曲が出るので、「参加する」を押せば途中からでも入れます(1分ごとに確かめます)。通行証は中継サーバーが再起動しても使えますが、持ち主がパスワードを変えると使えなくなります(その時は、もう一度リンクから入ります)。
   また、持ち主が `Ctrl+Alt+M` を押すか、拡張機能アイコンの「前に参加した人」で「招待」を押すと、招待が届きます。**音楽サービスのページを開いていなくても、ブラウザが起動していれば**、通知音が鳴り、Windows の通知と、拡張機能アイコンに「!」が出ます。
4. 通知の「参加する」か、アイコンを押して出る画面の「参加する」を押すと部屋に入り、**自分で選んだ音楽サービス**のタブが開いていなければ自動で開きます(開いていれば、そのタブを前に出します)。ほかのサービスのタブ(動画を見ている YouTube など)が開いていても、曲は選んだサービスのタブで流れます。招待は2分で消えます。「断る」を押すと、持ち主に伝わります。
5. 名前と使っているサービスは、拡張機能アイコンを押した画面の「あなたの設定」でいつでも変えられます。

### 一緒に聴いたことのある人の部屋に入る

- 同じ部屋で一緒に聴いた人どうしは、お互いの拡張機能に「友達」として記憶されます(中継サーバーが再起動しても消えません)。
- 友達がどこかの部屋で曲を流していると、拡張機能アイコンに青い「♪」が付き、アイコンを押すと「参加できる部屋」に、その部屋・流れている曲・部屋にいる人と「参加する」ボタンが出ます。押すとその部屋に入り、自分で選んだ音楽サービスで同じ曲が流れます。
- **同時に入れる部屋は1つだけ**です。別の部屋に入ると、前の部屋からは自動で出ます。
- PC Status(エージェント)を入れている人どうしは、最初から友達です(合言葉が同じ仲間なので)。たとえば Toro は、Skeliy の部屋で曲が流れていれば、一度も一緒に聴いていなくても「参加する」で入れます。
- Discord のリンクから来た人は、最初は Skeliy の部屋だけに入れます。そこでほかの人と一緒に聴くと、その人たちとも友達になり、その人たちが曲を流している時に入れるようになります。
- 拡張機能だけの人が、どの部屋にも入らずに1人で曲を流している時は、自動で「自分の部屋」が開き、右下に「友達が入ってこられます」と出ます。友達のアイコンには「〇〇 の部屋」として出ます。入ってきた人がいる時は、右下の「終了」で全員を部屋から出せます。

### だれでもホストできる(パスワードは同じ)

持ち主のPCが止まっている時でも、パスワードを知っている人がホストとして部屋を開けます。パスワードは持ち主の `config.json` の `listen_password` のままです。

- **前に参加したことがある人**: 拡張機能アイコンを押すと、「参加できる部屋」に「今は開いていません(あなたがホストとして開けます)」と出るので、「ホストする」を押します。音楽サービスのタブが開き、右下に「あなたがホストの部屋」と出ます。ほかの人は、いつもどおりリンクかアイコンの「参加する」で入れます。
- **参加ページ(Discord のリンク)から**: 部屋が閉じていてだれもホストしていない時は、ページに「ホストとして開く」と出ます。名前・サービス・パスワードを入れると、あなたがホストになります。
  - 中継サーバーが再起動した直後は、パスワードが正しいかを確かめられないため、参加ページからは開けません。その時は、前に参加したことがある人が拡張機能アイコンから「ホストする」を押してください(通行証の中に、部屋の鍵を暗号化したものが入っていて、それで開き直せます)。一度だれかが開けば、参加ページからも開けるようになります。
- 2人が同時に「ホストする」を押しても、ホストになるのは先の1人だけで、あとの人は参加になります。
- だれがホストかは、右下の参加者の一覧とアイコンの画面に「ホスト」の印で出ます。ホストが「退出」を押したりタブを閉じたりすると、残っている人に引き継がれます(「〇〇 がホストになりました」と出ます)。
- 持ち主のエージェントが起動した時にほかの人がホストをしていれば、エージェントはホストを奪わずにその部屋に参加します。そのホストが出ると、エージェントがホストを引き継いで部屋を開いたままにします。
- 持ち主のパスワードを変えると、古い通行証では開けなくなります(もう一度リンクから入ります)。
- PC Status(エージェント)を入れている友達も、参加ページか拡張機能アイコンから入った・ホストした部屋があれば、そちらを使います(Ctrl+Alt+M のリクエストを許可して友達の部屋に入っている時は、そちらが優先です)。

### Discord のステータスに「一緒に聴く」ボタンを付ける

Discord の「プレイ中」の表示(Apple Music の再生中の表示)に、参加ページを開くボタンを付けられます。

1. `apple-music-discord-presence\bridge` フォルダに `listen_url.txt` を作り、参加ページのURL(例: `https://pc-status-relay.onrender.com/listen/skeliy`)を1行だけ書きます。
2. エージェントの `config.json` に `listen_password` を書き、エージェントを起動し直します(パスワードが無いとボタンは出ません)。
3. ブリッジを起動し直します(タスクマネージャーでブリッジの `node.exe` を終了してから、ブリッジのショートカットを実行)。
4. Discord の「設定 → アクティビティのプライバシー」で「アクティビティステータスを表示する」がオンになっていることを確かめます。

- ボタンは、部屋が開いていてパスワードが設定されている時だけ表示されます(60秒ごとに確かめます)。
- Discord の仕様で、ボタンは**自分の画面には表示されません**。ほかの人があなたのプロフィールやメンバー一覧を見た時だけ表示されます。確かめる時は、友達に見てもらうか、別のアカウントで見てください。

### 拡張機能の入れ方

Chrome・Brave・Edge で使えます(Firefox は非対応)。

- **エージェントを動かしているPC**: 拡張機能ページ(`chrome://extensions` など)でデベロッパーモードをオンにし、「パッケージ化されていない拡張機能を読み込む」で **agent.py と同じフォルダの中の `extension` フォルダ** を選びます。拡張機能も自動アップデートで新しくなり、自分で読み込み直します。
- **Discord のリンクから来た人(Windows)**: 参加ページに出るコマンド `irm https://pc-status-relay.onrender.com/listen-install.ps1 | iex` を PowerShell に貼り付けて実行し、表示されたフォルダ(`%LOCALAPPDATA%\ListenTogether`。場所はクリップボードにコピーされる)を同じ手順で読み込みます。
  - コマンドは、拡張機能を GitHub(このリポジトリの `agent/extension`)からダウンロードし、タスクスケジューラに「ListenTogetherUpdater」というタスクを登録します。このタスクが2時間ごとに `public/listen-update.ps1` を GitHub から取ってきて実行し、新しい版があればフォルダの中身を入れ替えます。拡張機能はそれに気付いて、自分で読み込み直します(一緒に聴いている最中は、終わってから読み込み直します)。管理者の権限はいりません。
  - やめる時は、拡張機能ページで削除してから `irm https://pc-status-relay.onrender.com/listen-uninstall.ps1 | iex` を実行します(タスクとフォルダが消えます)。
  - 更新の記録は `%LOCALAPPDATA%\ListenTogether\update.log` に残ります。前の版で `ListenTogether\extension` に入れた人は、そのフォルダが引き続き更新されます。
- **Discord のリンクから来た人(Mac)**: 参加ページの入れ方の上にある「Mac」のタブを押し、出てくるコマンド `curl -fsSL https://pc-status-relay.onrender.com/listen-install.sh | bash` をターミナルに貼り付けて実行します。拡張機能ページの「パッケージ化されていない拡張機能を読み込む」を押したら、`Cmd+Shift+G` → `Cmd+V` → `Return` → 「選択」で、表示されたフォルダ(`~/Library/Application Support/ListenTogether`。場所はクリップボードにコピーされる)を読み込みます。
  - コマンドは Windows と同じく GitHub から拡張機能をダウンロードし、launchd(Mac の自動実行)に `com.skeliy.listentogether.updater` を登録します。ログインしている間、2時間ごとに `public/listen-update.sh` を GitHub から取ってきて実行し、新しい版があればフォルダの中身を入れ替えます。管理者の権限はいりません。
  - やめる時は、拡張機能ページで削除してから `curl -fsSL https://pc-status-relay.onrender.com/listen-uninstall.sh | bash` を実行します。
  - 更新の記録は `~/Library/Application Support/ListenTogether/update.log` に残ります。
- **コマンドを使いたくない人**: 参加ページの「zip で入れる」からダウンロードした zip を展開して、同じ手順で読み込みます。zip で入れた場合は自動では新しくなりません。
- **版の番号の決まり**: 拡張機能の版の先頭の数字(`3.2.0` の `3`)が上がった時だけ、古い版の人は参加ページで入れ直しを求められます。それ以外の細かい修正では「新しい版があります」と出るだけで、古い版のままでも参加できます。部屋のやり取りの形を変えるなど、古い版と一緒に使えなくなる変更をした時は、先頭の数字を上げてください。
- どちらも、デベロッパーモードはオンのままにしておいてください(オフにすると拡張機能が止まります)。
- 拡張機能アイコンは、ブラウザ右上のパズルのマークから「固定」しておくと、招待の「!」や人数が見やすくなります。
- 招待の通知が出ない時は、Windows の「設定 → システム → 通知」で、使っているブラウザの通知がオンになっているか確かめてください(通知が出なくても、通知音とアイコンの「!」は出ます)。

### config.json の項目

| 項目 | 内容 |
|---|---|
| `listen_room` | 自分の部屋の名前(英小文字・数字・ハイフン、32文字まで)。空なら `pc_id` |
| `listen_password` | Discord のリンクから入る人のパスワード。空なら、リンクからは入れない(友達の Ctrl+Alt+M だけ) |
| `music_service` | 自分が使っているサービス(`apple` / `spotify` / `ytm` / `youtube`)。リクエストを許可した時に、まだブラウザで開いていなければこのサービスのページを開く。空でも、一度使えば覚える |
| `music_hotkey` | ショートカットキー(初期値 `ctrl+alt+m`) |
| `music_sound` | 通知音(初期値 `notify.wav`。1.5秒ほどの短い効果音。空 `""` で鳴らさない。好きな `.wav` のファイル名に変えてもよい) |

### 注意

- それぞれのサービスに登録してログインしている必要があります。登録していないと、試聴しか流れなかったり、広告で曲がずれたりします。
- Spotify・YouTube Music・YouTube には、ページから操作するための公開された仕組みが無いので、拡張機能はページの中のプレイヤーや画面の操作で動かしています。サービス側の画面の作りが変わると動かなくなることがあります。Spotify の内部の仕組み(非公開のAPI)は、Spotify の利用規約で禁止されているので使っていません。
- Spotify が動かない時は、Spotify のページで開発者ツールのコンソールを開いて `window.__pcsSpotifyDebug()` と打つと、調査用の情報が出ます。
- ブラウザが自動再生を止めた時は、音楽サービスの画面右下に「再生」ボタンが出るので、1回押してください。
- 拡張機能とエージェントは、このPCの中だけで `http://127.0.0.1:8788` を使って話します(外からは繋がりません)。

## セキュリティ上の注意

- `WRITE_TOKEN` は「誰でもなりすまして状態を書き込めるか」を分ける鍵です。ソースコードに埋め込んだままGitHubの公開リポジトリにpushしないでください(公開する場合は環境変数化し、コードには埋め込まないこと)。
- `VIEW_TOKEN` は友達に共有する前提ですが、リンクごと不特定多数に公開されると誰でも全員の稼働中アプリ名を見られてしまう点は理解した上で共有してください。
- 表示される内容(開いているアプリ名やゲーム名、カスタムステータス)はそれなりに個人的な情報です。あらかじめ参加者全員にどんな情報が共有されるか説明し、同意を得たうえで導入することをおすすめします。
- 今回の認証は簡易的な共有シークレット方式です。身内利用を想定した最小限の実装なので、より高いセキュリティが必要であれば、参加者ごとに別のトークンを発行する、といった強化も可能です。

## トラブルシューティング

| 症状 | 確認すること |
|---|---|
| ダッシュボードが「まだ誰も接続していません」のまま | agent.pyが起動しているか、config.jsonの`server_url`/`write_token`がサーバー側と一致しているか |
| ダッシュボードを開くと `unauthorized` と表示される | URL末尾の `?token=...` が `VIEW_TOKEN` の値と一致しているか確認 |
| ダッシュボードに赤いエラーバナー | ブラウザの開発者ツール(F12)のConsole/Networkタブでエラー内容を確認 |
| agent.pyが `pip install` 後も動かない | `pip install -r requirements.txt` を再実行し、Pythonのバージョン(3.8以上推奨)を確認 |
| カスタムステータスのページが開けない | `http://127.0.0.1:8787/` のポート番号がconfig.jsonの`local_ui_port`と合っているか、agent.py実行中か確認 |
| オンラインなのに表示が更新されない | agent.py側のログでPOSTが成功しているか確認。ファイアウォールがoutboundを塞いでいないか確認 |
